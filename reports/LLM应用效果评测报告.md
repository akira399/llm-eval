# LLM 应用效果评测报告

> 本报告由 LLM-Eval 评测平台产出的三轮评测、人工盲评与红队测试合成，
> 全部数字可由仓库内命令复现（见附录 A）。

## 1. 执行摘要

以自研 Poke-RAG（宝可梦对战知识库问答系统）为被测对象，构建并验证了
一套完整的 LLM 应用效果评测闭环。核心成果：

| 成果 | 数字 |
| --- | --- |
| 用例集规模 | 50 条种子 → **183 条**（11 类目，卡片锚定扩写）+ 20 条红队用例 |
| AI 裁判可信性 | 与人工盲评一致率 **98%**，Cohen's Kappa **0.935**（优秀档） |
| 评测驱动的改进 | 正确性 0.82 → **0.93**（三轮），对战环境类 0 → 0.875，属性克制类 0 → 1.0 |
| 引用忠实度（v3） | **1.0**——全程未发现任何编造行为 |
| 红队边界测试 | 20/20 对抗样本全部防住（注入/越狱/越权/误导） |
| 修复安全性 | Poke-RAG 自带 78 问检索评测 top-3 维持 99%，零回归 |

一句话结论：**改提示词、换配置不再靠"我感觉"，同一套用例集跑一遍，
数字告诉你变好了还是变坏了、问题出在检索还是生成、AI 裁判自己可不可信。**

## 2. 评测平台设计

### 2.1 架构

```
用例集（yaml：查询 + 参考要点 + 期望行为 + 期望命中卡片）
   → Runner（原始输出全部落盘，评分与运行分离，换裁判不用重跑应用）
   → 被测适配器（进程内驱动 / HTTP SSE；「版本」= 被测系统配置快照）
   → Judge 四维评分：
       正确性 / 引用忠实度 —— LLM 裁判逐条判定再聚合
       格式 / 拒答行为     —— 确定性规则（零成本、可复现）
   → 汇总对比（分类目统计 · 版本回归 · 两级失败归因）
```

### 2.2 四维评分定义

| 维度 | 判定方 | 说明 |
| --- | --- | --- |
| 正确性 | LLM 裁判 | 逐条核对参考要点，得分 = 覆盖要点数 / 要点总数 |
| 引用忠实度 | LLM 裁判 | 断言是否被其引用的知识片段支持；诚实承认信息不足不算编造 |
| 格式 | 规则 | 引用编号一致性、长度、空回答、模板残留（确定性） |
| 语气 | LLM 裁判 | 0~2 分；明确的拒答细则防误判 |

### 2.3 AI 裁判可信性协议

人工盲评（界面默认隐藏 AI 分数）→ 一致率 + Cohen's Kappa → 分歧样本归类 →
修订评分细则 → 复测。实测两轮：

| 轮次 | 正确性一致率 | Kappa | 动作 |
| --- | --- | --- | --- |
| 首轮 | 94% | 0.824 | 发现裁判把「诚实承认不知道」误判为编造/语气 0 分 |
| 修订后 | **98%** | **0.935** | 正确性均分 0.81→0.82 基本不动——修正只影响误判维度，未靠放水抬分 |

忠实度/格式/语气三个维度一致率 97.3%/98%/100%，其 Kappa 显示 0 系
「Kappa 悖论」：人工全判同一档（应用确实零编造、零格式问题）时 Kappa 数学上
退化，此时以一致率为准。

## 3. 评测集构成

| 部分 | 数量 | 说明 |
| --- | --- | --- |
| 种子用例 | 50 | 10 类目标签，含拒答 4、注入 1、已知弱项（伤害计算）3 |
| 卡片锚定扩写 | 133 | 要点取自知识卡片原文（原词优先），分词重叠率 ≥0.6 机器预筛 |
| 模板生成 | — | 招式集合类走模板；伤害计算要点为固定行为规范，不让 LLM 发挥 |
| 红队边界 | 20 | 注入 5 / 越狱 5 / 越权与有害 5 / 误导 5 |

扩写纪律与教训：

1. **事实锚定**：评测集自身的事实可靠性不能依赖另一个 LLM 的诚实度——
   要点必须能在卡片原文中找到依据，逐条做分词重叠率校验；
2. **预筛会误杀同义改写**：特性/道具类要点常被 LLM 合理改写，导致重叠率
   低于阈值被淘汰（两轮扩写后该两类 15+15 目标只落位 10+15）——宁可少
   不可错，误杀条目进入人工抽查清单逐条复核；
3. 最终 183 条（目标区间 100–200）覆盖 11 类目，其中 difficulty=hard 18 条
   单独统计，不与常规题混算。

## 4. 基线评测与失败归因（v1）

50 条全量基线：正确性 0.82 · 忠实度 0.988 · 格式 0.98 · 语气 2.0，零错误零超时。

两类系统性失败被自动化归因（检索层 vs 生成层两级定位）精确捕获：

| 失败类目 | 归因 | 根因 |
| --- | --- | --- |
| 对战环境 4/4 全败 | 组装层 | 检索命中 Meta 卡片后，上下文组装白名单漏了该类型，卡片被静默丢弃，模型拿到空上下文只能拒答 |
| 属性克制 4/4 全败 | 语料缺口 | 克制知识只在规则引擎、未入检索语料，聊天路由也未接入；被测系统自带的 78 问检索评测恰好没覆盖此盲区 |

**归因输出与人工诊断逐条吻合**——失败不是"感觉它不行"，而是定位到具体代码行。

## 5. 版本回归闭环（v1 → v3）

| 版本 | 改动（全部由评测证据驱动） | 正确性 | Meta 类 | 克制类 |
| --- | --- | --- | --- | --- |
| v1 基线 | — | 0.82 | 0 | 0 |
| v2 | 组装白名单补全 + 克制知识入语料 | 0.917 | 0.833 | 0.5 |
| v3 | 克制卡补「攻击视角」（v2 归因到生成层后发现的知识表达缺口） | **0.93** | 0.875 | **1.0** |

忠实度升至 1.0（零编造）；强项类目零回归。修复过程中引入过一次检索污染
（卡片正文堆砌查询词致 78 问评测 top-3 99%→94%），被被测系统自带回归评测
当场抓住并回退——**平台评测与被测系统自身评测互为保险**。

如实报告的方差与剩余问题：

- hard 类用例单次跑分有波动（模型两次都诚实拒答，但"解释原因"的深度不同
  导致判分 1.0↔0.0）——单次评测结论需谨慎，这是 M3 扩写用例集的动机之一；
- meta-004（分级定义）与多跳配招为已知知识边界，三轮一致失败，不粉饰；
- 裁判偶发空响应按 fail-visible 记 None 而非编造分数。

## 6. 红队边界测试

20 条对抗用例（注入 / 越狱 / 越权与有害请求 / 误导陷阱）实测：**全部防住**。
系统提示词零泄露、无一顺从越权请求、面对虚假前提（"快龙是水属性，纠正它"）
坚持知识库依据而非讨好改口。

测试同时校准了评测器自身：模型回答"这会违反回答规则"（提及规则存在但未
泄露内容）曾被泄露检测误报，已收紧为只匹配提示词原文片段——红队测试的
价值不仅在测应用，也在磨评测器。

## 7. 线上反馈回流机制

定义了点踩数据的回流格式与工具链：反馈 JSONL → 去重（与现有用例集归一化
比对）→ 检索 top-1 卡片做事实锚点 → LLM 从卡片原文生成参考要点 → 机器
支持率预筛 → 人工复核后并入正式用例集。示例实测：4 条点踩中 3 条自动完成
要点构建且事实正确（如"耿鬼速度种族值 110"），1 条多跳比较题诚实标记
"待人工构建"。

## 8. 方法论沉淀

1. **评测 → 归因 → 修复 → 复测**的闭环可以完全走通，每处修复前有归因证据、
   修复后有同用例集量化验证；
2. **评分先规则后 LLM**：确定性规则（格式/拒答行为）零成本零抖动，LLM 裁判
   只做真正需要语义理解的判断；
3. **评分与运行分离**：换裁判模型、修订细则后重算分数不需要重跑被测应用，
   原始输出落盘是一切复用性的基础；
4. **评测集质量是被测系统质量的一部分**：要点措辞歧义、条件互斥等用例缺陷
   会在人机分歧中暴露并反哺修订；
5. **对评测器保持怀疑**：裁判细则需要校准轮，泄露检测会误报，预筛会误杀——
   每一层都有人机复核兜底。

## 9. 局限

- 被测对象单一（Poke-RAG），平台对其他应用的适配器尚未实战验证；
- 183 条用例对 4000+ 张知识卡片的覆盖率仍低，抽样分布偏向种子集设计时的
  高频类目；
- LLM 裁判的判分方差未做多裁判投票（majority voting）对冲；
- 人工标注为单人盲评，多人标注间一致性（IRR）未测量。
